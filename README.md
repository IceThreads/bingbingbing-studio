# 冰冰冰音乐工作室 · Bing Bing Bing Studio

一个纯前端（无依赖、无联网）的“冰冰冰”音乐**制作器 + 弹奏器**，已内置真实冰冰冰素材。

## 运行

直接双击 `index.html` 即可（Windows 也可以在该目录执行 `start index.html`）。
没有构建步骤，没有 npm 依赖。

## 内置素材

桌面上的 `冰冰冰音效 - audio.m4a` 已通过 `tools/embed-sample.py` 内嵌进 `sample-data.js`，
所以**打开页面就是真实冰冰冰音**，不需要任何额外操作。

载入时程序会自动分析素材，实测结果：

| 项目 | 值 |
|---|---|
| 容器/编码 | M4A (AAC)，18653 B，48 kHz，1.44 s |
| 前导静音 | **0.435 s**（原素材开头接近半秒无声，已自动裁掉，否则每次按琴键都会延迟出声） |
| 裁静音后 | 0.431 s → 1.393 s，共 0.96 s |
| 自动分段 | 3 段，即三个“冰”字：`[0.434~0.579]` `[0.579~0.749]` `[0.749~1.393]` |

因为“整段素材”其实是一句完整的“冰冰冰”（约 0.96 s），直接当一个琴键音会又慢又糊，
所以「触发方式」给了两种：

- **单个“冰”**（默认）：只触发第一段（0.43→0.58 s，约 149 ms），琴键手感跟手，适合打节奏；
- **整段“冰冰冰”**：一次把三个字都打出来，适合做点缀或前奏。

另外还有「试听原素材」按钮，可以听未经裁剪的完整原声。

## 功能

### 弹奏器
- 16 块冰砖，点击或按电脑键盘发声：
  - 高音区：`Q W E R T Y U I`（D5 起的 C 大调）
  - 低音区：`Z X C V B N M ,`（C4 起的 C 大调）
- `长按持续震冰`：按住键会每 110ms 重触发一次，做出“冰冰冰冰”的连打效果。
- 录制：点「开始录制」再弹，停止后点「量化到制作器网格」，节奏会自动对齐 16 分音符、按音高分配到各条轨道。

### 制作器（钢琴卷帘 / 内部就是 MIDI）
- **一行一个音高**：C4 ~ C6 共 25 行，高音在上，黑键行底色略深——不是 8 轨鼓机，而是一块能写旋律的卷帘。
- **每个音符都带时值和力度**（等同于 MIDI 的 note on/off + velocity，存在稀疏表 `durs` / `vels` 里）：
  - 浅色尾格 = 这个音持续中；`Shift+点` 拉长一格、`Alt+点`/右键 缩短一格；
  - 「画笔时值」1/2/4/8/16 格决定新画的音符多长，「画笔力度」决定多重；
  - 力度大的格子更亮、小的更暗（`vel-hard` / `vel-soft`）；
  - 播放时**长音真的响更久**（≥2 拍的音中途会自动补两次轻击），**重音真的更响**。
- 8/16/32/64/128 步，每 4 格一拍；点格子开关，按住拖动连续涂抹；点左边的音名可以试听那一行。
- 每行可调力度、静音 M、独奏 S、清空 ×；「只显示有音符的行」可以把 25 行收成实际用到的那几行。
- 传输：速度 50–200 BPM、摇摆、节拍器、循环。
- 预设：`经典冰冰冰`、`Bang 副歌感`、`冰原回响`；另有 `随机冰雹`。
- 音色：亮度、长度、力度、音高偏移、混响大小、混响量。
  - 采样模式下「力度 / 音高」生效，「亮度 / 长度」只作用于合成冰音。
- 保存到浏览器（3 槽位）、导出/导入 JSON、导出 WAV（44.1kHz / 16bit 立体声）。
  - 存档格式为 v2（行=音高）；v1 的 8 轨旧存档读入时会按音高自动迁移过来。

### 导入音乐 · 自动编曲

把任意歌曲（`.mp3 / .m4a / .wav / .flac`…）拖进「导入音乐」卡片，设好截取区间后点「自动编曲」，
程序会把它转成冰冰冰网格：

1. **混单声道 + 重采样**到 22050 Hz；
2. **STFT 谱通量**（1024 点 / hop 256）得到起音包络，同时统计每帧的低频占比与频谱重心；
3. **自适应阈值 + 峰值挑选**取出节奏点（局部均值 + k×标准差，`灵敏度` 就是这个 k）；
4. **自相关测速**：加梳状加权与 120 BPM 对数正态先验，折到 70–180 之间；
5. **音高提取**（仅「旋律」模式）：**先逐帧跟踪连续基频，再切成音符**（不是“一个起音估一次音高”）：
   - 每 11.6 ms 一帧做谐波求和（HPS），搜索范围 200–1300 Hz——贝斯/底鼓的基频直接落在范围外；
   - 在“分数 ≥ 最高分 55%”的候选里，按「离最近 15 帧的**音高中值**要近（≤7 个半音，旋律不会瞬间大跳）
     + 音越高越优先（主旋律通常是最上声部）」挑一个；
   - 用 contrast 判断这一帧算不算乐音，短空档（换音瞬间的分析窗混叠）用**保持前一个音高**补上，
     避免换音瞬间掉到伴奏声部产生假音；
   - 基频用幅度谱抛物线插值精确到 1 Hz 级（不做插值会偏半个半音，G4 会被读成 G#4）；
   - 最后把音高稳定的连续帧合并成音符（音高变化或断开就切分），按 `音阶` 吸附后折进 C4–C6 音域；
6. **量化 + 落行**：所有起音对齐 1/16 格；**每个音高落到自己那一行**（最多 25 行，不再压缩成 8 条轨，
   所以一首有十几个音的旋律也能完整弹出来），行的力度取该行平均强度；
7. **谱子输出**：把扒出来的音按时间排成音名序列（如 `C5 D5 A4 E5 …`）显示在界面上，方便你核对。

| 选项 | 说明 |
|---|---|
| 起点 / 长度 | 截取整首歌里的一段来分析（默认取 8 秒） |
| 音高 | **默认 `旋律（扒谱，推荐）`**：提音高、把谱子扒出来；`单调（纯节奏）` 把每个节奏点都打在同一个音上——**只扒节奏不扒音高**，原梗那种“冰冰冰”就是这个味道（注意：用这个模式看「谱子」当然全是同一个音名） |
| 音阶 | 大调 / 小调 / 五声 / 不吸附，旋律按所选音阶吸附 |
| 灵敏度 | 越大越严格（漏掉弱音），越小越容易把杂音当节奏 |
| 速度 | `自动检测` / `自动 ÷2` / `自动 ×2` / `手动指定 BPM` |
| 节奏密度 | 全部(1/16) / 只保留 1/8 / 只保留 1/4，太密时用它减负 |
| 生成后自动播放 | 编完自动跳到网格并试听 |

**旋律模式的几个关键处理**（否则结果会很脏，都是实测踩出来的）：

| 处理 | 为什么需要 |
|---|---|
| 只在 200 Hz 以上找音 | 自相关/全频搜索会被贝斯带跑（实测整首歌的主旋律被识别成 38~45 的贝斯音） |
| 轨迹法 + 7 个半音的连续性门 | 真歌每 0.25 s 就有一堆鼓/镲/词起音，「一起音一音高」会扒成密集八分音符串，还大量重复同一个音 |
| 换音瞬间保持前一个音高 | 分析窗横跨两个音时频谱混叠，会短暂掉到伴奏声部（实测掉到 220 Hz 变成 G4/A4 假音） |
| 幅度谱抛物线插值 | 候选按 FFT 频点取整（10.8 Hz 一格）会偏半个半音，G4(392 Hz) 读成 409 Hz → 变成 G#4 |
| 噪声门限用 contrast | `contrast = 最佳候选分数 / 平均候选分数`：噪声帧里各候选分数都差不多（实测镲片 1.5~2.5，乐音 5~34） |
| 判不出音高的起音直接丢弃 | 兜底塞成同一个音会让整份“谱子”变成一排同样的音名，看起来就像什么都没扒出来 |

如果这段音频里几乎没有稳定乐音，程序会直接告诉你「没找到旋律，换个片段或改用单调模式」，而不是给你一排假音。

**关于速度二义性**：半速/双速是测速算法的固有难题（比如 90 BPM 的歌配八分音符 hi-hat，很容易被判成 178 BPM）。
识别偏了不影响节奏本身（格子只是变细），但会缩短能覆盖的时长，这时用「自动 ÷2 / ×2」或「手动指定 BPM」修正即可。

**关于扒谱的边界**：这是**单声部旋律提取**，假设主旋律是最突出的高声部（真实歌曲里通常就是人声/主奏乐器）。
所以：

- 人声/主奏清楚的段落，扒得挺准（演示曲 88% 逐音命中）；
- 鼓组密集、编曲很厚的段落会多出一些音符（同一段里音符数会偏多）；
- 纯打击乐、纯环境音、以及完全没有主旋律的段落，会明确报「没找到旋律」，不会硬给你一堆假音。

想更干净：提高 `灵敏度`、`节奏密度` 选 1/8、或者只截取副歌那 8 秒。

### 一键示例曲

不想找素材就直接点「用示例曲试一次」：`demo-song.js` 会**现场合成**一段 100 BPM 的小曲
（底鼓/军鼓/踩镲 + 贝斯 + 和弦垫 + 主旋律），然后自动走一遍编曲并播放，用来快速确认功能是好的。

### MIDI

- **导出 MIDI**：标准 SMF（format 0，480 ticks/四分音符），带 tempo、音高、时值、力度，
  可以直接拖进 DAW / MuseScore / FL Studio。
- **导入 MIDI**：任何 `.mid` 都能变成冰冰冰。**整首歌的 MIDI 动辄几千格**（实测一份 3 分 49 秒的谱子是
  **1526 格 / 511 个音符**），网格装不下，所以是**分段导入**：
  1. 选文件后先分析，面板上显示「音符数 / BPM / 总格数 / 第一个音在第几格」；
  2. 自动跳到**第一个有音符的小节**（这份文件的第一个音在第 160 格——前面是全空的前奏，
     以前从第 0 格开始导入，屏幕上一片空白，看起来就像“解不出来”）；
  3. 按段落音高的中位数**整段自动移调若干个八度**，好落进 C4~C6 的 25 行里；
  4. 「下一段 ▶」一段段往后听，或直接改「起点格」；
  5. 勾上「只要主旋律」时，同一格只留最高的那个音（MIDI 里通常还有伴奏和低音声部）。
- 内部数据模型本来就是这个结构，所以往返一致：实测「编码 14 个 → 解回 14 个，BPM/时值/力度都保住」。

**下一步（还没做）**：Python 高精度通道 —— `demucs` 先把人声分出来，再用 `basic-pitch` / `pyin`
扒谱输出 `.mid`，直接拖进「导入 MIDI」即可。这样想要高准确率就走 Python，普通用户仍然双击 `index.html` 就能玩。

## 音源：让“冰”能弹出旋律

这一步是「扒谱弹奏」能不能听出来的关键。素材本身就是声音的“音色”，有两件事必须处理对：

1. **采样根音（音高对齐）**：载入素材时会用自相关测出素材本身的音高，
   自动设为采样根音（本素材实测 **A#4 ≈ 460 Hz**，清晰度 0.94，是明确的乐音）。
   如果这个值设错（比如默认按 C4 算），整条旋律会被整体移调，而且**播放速率一变，
   本来就短的“冰”会被压得更短**——原来每个音只剩 84 ms，听起来就是一串“哒哒哒”，
   这正是“不像曲子”的直接原因；修正后同一位置是 129~258 ms。
2. **音高感**：原素材每个“冰”只有 145 ms，光靠它音高感很弱。所以默认叠一层
   **按音符频率衰减的正弦体**（`音高感` 滑杆，默认 0.35，0 = 纯素材原味）。
   实测离线渲染后反测音高：C4/E4/G4/C5/E5/G5 六个音全部落在 **4~49 音分**以内（一个半音是 100 音分）。

另外**节拍器默认关闭**了——开着它听编曲结果只会听到一片“嘀嘀”。

## 换素材

**拖进去就行**：「制作器 → 音源 → 采样音源」，把 `.m4a / .wav / .mp3` 拖进虚线框
（只在本地用 Web Audio 解码，不上传）。载入后会自动裁静音、自动分段、自动识别音高。

**想变成永久内置**（双击即用）：

```powershell
py tools/embed-sample.py "C:\path\to\冰冰冰音效 - audio.m4a" --name 冰冰冰 --root 60
```

- `--root` 是采样根音（默认 60 = C4）：按素材本身的音高设，按这个音时原速播放，其他音做变调。
- `--reset` 清空内嵌素材，回到占位状态。
- 脚本不做转码，直接 base64 内嵌原文件，同时把原文件复制到 `samples/` 留档。

## 关于“正确的冰冰冰”

“冰冰冰”本身不是官方素材，是流传很久的网络梗音效，网上至少三套说法混在一起：

1. **游戏梗**：出自歌曲《Bang Bang Bang》副歌的空耳，被当成《王者荣耀》橘右京“专属击杀 BGM”，UP 主“君顾”的视频带火；
2. **更早的抽象原声**：贴吧“失传媒体吧”考证其 2017–2018 年已广泛流传，更早出处不明（另有“1995 年加拿大公司音效库”的说法，未证实）；
3. **近期二次爆火**：2026 年 9 月起“老牧师音效”系列（`哎呦我去` `巴哈哈哈哈` `血肉爆裂` `冰冰冰`…）在抖音/B 站被大量二创。

本项目现在用的就是你提供的那份 `冰冰冰音效 - audio.m4a`；内置的**合成冰音**（`audio-engine.js` 的 `_playSynth`：下滑音头三角波 + 泛音层 + 冰裂噪声 + 820Hz/2350Hz 双共振峰）仍保留，可在「音源 → 合成冰音」一键切回。

## 实现要点

- 音频全部由 Web Audio API 实时生成/播放，唯一的音频资源是内嵌的 base64 素材。
- 音序器使用 lookahead 调度（20ms 轮询 + 120ms 预排），速度稳定、不受界面卡顿影响。
- 导出 WAV 用 `OfflineAudioContext` 离线重放同一套引擎，再手写 RIFF 头编码成 16bit PCM。
- file:// 下浏览器不允许 fetch 本地文件，所以素材走 base64 内嵌而不是读取 `samples/` 目录。
- 调试句柄：控制台里可以用 `BING_STUDIO.state` / `BING_STUDIO.engine` 查看或改状态。
